## Decision gates (owner/gate calls, resolve before the noted slice — not code)
- **D1 — RESOLVED (owner 2026-09-11, superseding the machine-wide choice): PER-SLICE, asserting one-slice-per-box.** CPU is a SECOND PER-SLICE scalar in the same ledger as RAM (`queue.cpuOutstanding` vs the `2 × NumCPU` ceiling); conjunctive fit and per-slice wait/wake, exactly parallel to RAM — no machine-wide CPU ledger, no cross-queue signal. Rationale: on this box every confine uses `aira.slice` (one slice in practice), and the initial machine-wide implementation (a `Server.cpuByQueue` map) bred a measured cross-slice over-admit (a pruned queue's stale pass erased its same-path successor's charge → Σ=5 > ceiling 4, Fable P1). Per-slice makes that class unrepresentable by construction. **Cores are machine-wide: if multiple concurrent slices are ever introduced, CPU must become machine-wide (sum across slices) — revisit then.** Documented at `cpuCeiling`/`sliceQueue.cpuOutstanding` in `admit.go`. [map4 RISK-1 is moot under per-slice: there is no single cross-queue FIFO to re-evaluate.]
- **D2** (at S4): fate of the AIRA-103/106 pressure ceiling (`sliceceiling.go:722-773`) — keep (feeds a smaller ceiling, loop unaffected) or delete. [spec §7]
- **D3** (run the measurement spike ∥ Phase 1; decide before S15/S16): §13 fork — worker connection stays in the Go relay (no Python encoder needed) vs moves into `supervisor.py` (needs a Python ARDR encoder + shared golden fixture). Spike = N Python sockets reconnecting at 2/sec on localhost; pure measurement, no daemon code.
- **D4 — RESOLVED (owner 2026-09-11): MODE-DEPENDENT, not a blanket retire.** CI mode = **ledger-only** (declared reserves; the container `memory.max` is the cap; nothing runs outside the slice, so the ledger is the truth). DEV mode = **KEEP a physical gate that checks actual SYSTEM-available RAM** (plenty runs outside `aira.slice` on the desktop, so a new admission must be refused when the *system* is low even if the slice ledger shows room). So S4 makes `checkedAvailable` MODE-GATED (dev keeps it, reading system-available RAM; CI drops it), NOT deleted. The `worker_admit` live-usage guard (S15) follows the same CI-vs-dev split. Mode = ci-shim/advisory vs real-cgroup daemon.
- **D5 — RESOLVED (owner 2026-09-11): ACCEPT the gap.** `--exclusive`/drain emptiness = `Σleases==0`; an orphaned RAM holder that lost its lease reads "empty" so `--exclusive` could be granted beside it — accepted as bounded (MemAvailable watchdog + `oom.group` catch the worst case). No guard built. Applies at S14.
