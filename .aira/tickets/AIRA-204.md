Finish AIRA-20's deadline discipline in the packages it excluded: four witnessed merge-gate flakes, each a different defect class
**kind** chore · **severity** P1 · **closes** RANT-9, RANT-27

**SYMPTOM.** The pre-push merge gate is load-dependent: `.githooks/pre-push` → `Makefile:88 ci: fmt-check vet build test` → `go test ./... -count=1 -timeout 20m`, one attempt, no retry. A false fail costs a whole ~8-minute cycle, and has already **refused a legitimate push** (recorded at `.aira/tickets/AIRA-176.md:126-128`). Four witnessed offenders, three packages, two with three independent sightings each: `TestMCPConfineKillOutsideProjectKeepsOwnershipAndStealChecks` (cmd/aira; RANT-9, RANT-27, AIRA-35), `TestTUIKeypressAndQuitWhileFetchAndQueueUpdateAreInFlight` (cmd/aira; RANT-9), `TestRealRunTimeoutKillsProcessGroup` (gitremote; RANT-27, AIRA-144, AIRA-176), `TestRealCgroupDynamicChargeTracksMemoryCurrentAndFreesAWaiter` (daemon; RANT-27). AIRA-20 scoped its pass to `internal/{runner,daemon,pylib}` and records only `cmd/aira` as excluded (`AIRA-20.md:116`); gitremote/store/install/core are never named, so the class reads as closed and is not.

**ROOT CAUSE — four different defects; `testdeadline` fixes exactly one.**
- **A (cmd/aira, readiness poll on the wrong signal).** `cmd/aira/dispatcher_inprocess_test.go:1057` opens a 5s poll whose break condition at `:1062` is `strings.Contains(output, name) && strings.Contains(output, "session-a")` — both strings derive from the scope **directory name** (`internal/runner/confine_manage_linux.go:182`, `scopeID := strings.TrimPrefix(entry.Name(), ".aira-")`, comment at `:187`). The directory exists before the child is placed in `cgroup.procs`. The kill then gates on something else: `confine_manage_linux.go:621` returns `U_CONFINE_NOT_LAUNCHED: scope %s has nothing to kill yet; retry` off `cgroup.events`. Only the `--steal` call at `:1082` is exposed — `confine_manage_linux.go:581-582` returns `CodeConfineOwnerUnverified` before the population gate, so `:1078` is immune.
- **B (cmd/aira, hard fatal nested inside a retry budget).** `cmd/aira/tui_smoke_test.go:76` opens a 1s budget; the two-arm select at `:81-88` has `case <-time.After(100*time.Millisecond): t.Fatal("keypress deadlocked the tview loop")` at `:86-87`. One slow `QueueUpdateDraw` round-trip aborts the test instead of consuming one iteration — and the diagnosis in the message is false. **The identical nesting recurs at `:517`/`:528-529`.** Same class without the nesting at `:166`, `:279`, `:450`; `:296` is an unbounded receive with no backstop at all.
- **C (gitremote, nested-timeout inversion).** `internal/gitremote/exec_test.go:16` gives the whole subject `context.WithTimeout(..., 50*time.Millisecond)`, inside which `/bin/sh` must exec, install a TERM trap, fork `sleep 30` and printf two PIDs; `:29-30` then asserts two fields and fails `pid output=""`. The subject's own timeout is also the entire budget for the test's precondition. Output capture is not the problem (`exec.go:41-44` drains to EOF). This is the class AIRA-148 already named and guarded once in another package (`internal/runner/confine_deadline_danger_linux_test.go:177-188`).
- **D (daemon, unsettled fixture) — MECHANISM UNEVALUATED.** `internal/daemon/admit_dynamic_charge_real_cgroup_linux_test.go:75` returns at the first observation of `memory.current >= 64MiB` while the allocator script keeps materialising copies; the production scan (`:161`) and the test's own read (`:163`) sit at two points on a rising curve. Two assertions could fire in opposite directions (`:171-172` charge-too-high against a 256MiB margin floor; `:174-175` charge-too-low). RANT-27 records no message. **Do not fix blind.** Note this file has no `time.After` at all — no deadline helper would have caught it, and `internal/daemon` *was* swept.

**PROPOSED FIX.** **A:** break on the signal the kill gate uses — parse the `aira_confine_list` JSON and require the record whose `name` matches to have `subtree_populated == true` (`internal/runner/confine_manage.go:48`, set from the same `cgroup.events` source, left nil-never-false when unestablishable). Do **not** substring-match: the test launches into the real machine-wide `aira.slice` with `{}` arguments, so a bare `Contains(output,"subtree_populated\":true")` is satisfiable by a neighbour's job. Route the 5s poll and the 3s supervisor-exit wait through `testdeadline`. **B:** keep the timeout arm, retime through `testdeadline`, replace `t.Fatal` with `continue`. **Deleting the arm is worse than the bug** — the select has two arms, so removal leaves a blocking receive and a stall becomes a 20-minute hang that takes out the package. Fix the `:517` twin too. **C:** make the precondition a handshake — `runRequest` already carries `LiveStdout` plumbed at `exec.go:43-44`, so arm the deadline only after the pid line is observed. **Preserve `context.DeadlineExceeded`**: `:22` asserts `errors.Is(result.Err, context.DeadlineExceeded)` and a plain `WithCancel` yields `context.Canceled` and turns the test red 100 %. **D:** reproduce first, with the failure message and `memory.current` at `:161`/`:163` captured; then likely have the allocator write a completion marker and require two consecutive equal readings — settled, not merely above a threshold.

**HOW TO TEST.** A: a unit test of the predicate over `ConfineRecord` values (nil → poll, false → poll, true-but-different-`name` → poll, true-and-matching → break; the current predicate fails the third), plus an injected ~200 ms placement delay which fails at `:1082` today. B: queue a ~300 ms `QueueUpdateDraw` ahead of the probe — deterministic fatal today; plus a never-true case proving the outer assertion still fails, or the fix is vacuous. C: interpose a 200 ms sleep before the trap; today fails 100 %, fixed version still returns `DeadlineExceeded` and still proves the group was signalled, with an assertion that the kill happened **after** the pids were observed. D: the captured repro is the first deliverable.

**Recorded, not scheduled.** Raw `time.After(`/`time.Now().Add(` in `*_test.go` outside the three swept packages: cmd/aira 61, internal/store 13, internal/install 4, internal/core 2, internal/gitremote 1 = 81. **This count is not the work in either direction.** Five of internal/store's 13 are deliberately-correct negative waits that `testdeadline`'s own doc says it does not touch (incl. `outbox_retire_test.go:1157`, which carries a comment saying its flake direction is safe); four more are already 5s/30s/60s; no store flake has ever been witnessed. And the count *misses* the actual gitremote offender, which is a `context.WithTimeout`, not a `time.After`. internal/store, internal/install and internal/core are recorded here and not scheduled.

**Deliberately not done: no lint/CI guard against raw `time.After` in tests.** About half the raw sites in unswept packages are correct as written, so any guard needs an allowlist and the allowlist is the complexity the simplicity rule forbids. The discipline is holding without one: only five test files in the three swept packages have regrown a raw `time.After`, and AIRA-20's own resolution already classified two of them as correct-to-leave. `aira126Scale` is not a fork — it delegates to `testdeadline.Scale()` (`internal/runner/timeout_arbitration_linux_test.go:230-236`) for subject-side durations that must scale without the 5s floor.
