cmd/aira/main.go runSupervisor (at d13ef3b :660-664): readyFD, readyErr := strconv.Atoi(values["ready-fd"]); on a parse error Atoi returns 0, and the malformed-arguments branch calls writeSupervisorFailure(readyFD, ...), which wraps fd 0 in an *os.File, writes the JSON failure to it and closes it. The same function already computes readyForFailure := supervisorReadyFD(argv) (:642), which returns -1 for a missing or unparseable --ready-fd (so writeSupervisorFailure is a no-op). Fix: use readyForFailure in that branch (and audit the later writeSupervisorFailure(readyFD, ...) calls, which run only after a successful parse). Test: in-process runSupervisor with --ready-fd x must not close or write fd 0 (e.g. dup a pipe onto a spare number and assert it is still open). Found during AIRA-204/199 plan review (2026-10-11); no test reaches it in-process today. Product bug, not a flake.
