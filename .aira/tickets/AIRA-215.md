`E_TRANSITION_INVALID` names the refused edge but never the legal successors, so the ticket status graph is discoverable only by reading Go source
**kind** chore · **severity** P3 · **closes** RANT-11, RANT-18, RANT-26

**SYMPTOM.** `aira mv AIRA-175 in-review` from `planned` refuses with exactly `E_TRANSITION_INVALID: planned -> in-review`. It names the edge you cannot take, never the ones you can, and the complete legal-successor map is three lines above the format string. Three independent rants collided with this. There is no documented alternative: `docs/dev/agentic-development-loop.md` (4 KB) contains no `aira mv`, status or close-path guidance at all, and the one normative rendering of the graph — `docs/superpowers/specs/2026-08-08-aira-phase1-design.md:381-390` — is **stale**: its `done` row still reads `done -> retired | superseded`, but `e280ee4` added `done -> in-progress` on 2026‑08‑30 and did not update it. So an agent's two routes are the Go source or a spec that is wrong by one edge.

**ROOT CAUSE.** `internal/domain/ticket.go:179` — `return fmt.Errorf("E_TRANSITION_INVALID: %s -> %s", from, to)`, with the `allowed` map at `:165-177` in scope and unread. The house rule already exists nine lines below: `invalidFieldError` (`ticket.go:189`), whose doc comment says naming field + value + allowed set "is the point of AIRA-170's second half". Both production call sites inherit the message unchanged (`internal/store/mutate.go:60`, `internal/store/store.go:2297`, which also covers `aira set <id> status=`).

**PROPOSED FIX.** (1) Build the successor list from `allowed[from]`, sorted for stability, and name it: `E_TRANSITION_INVALID: planned -> done is not a legal transition; from planned the legal next statuses are: in-progress, retired, superseded`. **Terminal states must read honestly** — `retired` and `superseded` have empty successor sets, so emit "`retired` is terminal; it has no legal next status", never `allowed: ` with nothing after it. Keep the code and exit 1 unchanged; nothing pins the message text (`store_test.go:1141` is a `Contains` on the code, `core_test.go:514` and `skill_test.go:383` key on the code), so this breaks no test — which is itself the signal that the change is message-only. Prefer a function returning the successor set over a package-level mutable map. (2) Correct the spec's `done` row to `done -> in-progress | retired | superseded`. (3) Add one paragraph to `docs/dev/agentic-development-loop.md` stating the sanctioned close path (`aira mv <id> in-progress`, `in-review`, `done`, in that order; the ticket file's `status` is never hand-edited) — **and, while there, one sentence recording that the pre-push gate deliberately runs the full suite on every push because the repository's own content files are test oracles** (see §6.1).

**NOT IN SCOPE — the `planned -> done` edge stays refused (decided, not deferred).** Since RANT-26 was filed, 10 tickets have been moved through the verbs for **37 hops** (AIRA-176 ×1, 180 ×3, 182 ×6, 183 ×3, 185 ×3, 187 ×6, 191 ×5, 192 ×5, 196 ×3, 200 ×2), and the AIRA-196 burst spans ~94 ms. Two closes bypassed the verbs (AIRA-173, AIRA-176). Widening is not one line: `internal/core/core_test.go:514` pins in-progress→done as illegal and AIRA-176 shows closes recorded from in-progress too, so adding only the planned edge leaves the identical complaint available from in-progress — and it would amend the normative spec. **Accepted residual, recorded not hidden:** a hand-edited status in a committed file reaches neither call site, and `internal/store/check.go` structurally cannot check it (a committed file records a status, not a prior status).

**HOW TO TEST.** `ValidateTransition(StatusPlanned, StatusDone)` names `in-progress`, `retired`, `superseded`; same for `(Draft, Done)` and `(Done, Planned)`. `(Retired, Done)` says terminal and does **not** emit an empty allowed list — this is the false-pass direction a naive `strings.Join` introduces and it would pass vacuously against current code, so assert the terminal wording specifically. Assert the full string for determinism across repeated calls (a `for k := range` fix passes once then flakes on map order).

**Evidence hygiene.** The "4/4 recent closes hand-edit status" table must not appear in any form, including softened. It is false for 3 of its 4 rows — AIRA-196, AIRA-183 and AIRA-180 each took three legal `aira mv` hops recorded in the journal seconds before their close commit, and `.aira/tickets/AIRA-180.md:170-171` — a line added by one of the cited commits — reads "Ticket driven planned → in-progress → in-review → done via `aira mv`."
