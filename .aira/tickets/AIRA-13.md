Agents and humans will type decimal sizes like 1.5GB / 0.5G / 1.05G. Today the grammar is integer-only ([0-9]+ + unit) in BOTH runner.ParseMemorySize (Go) and the mirrored _parse_memory_size in the aira_xdist_governor (Python). Extend to an optional decimal fraction using EXACT INTEGER arithmetic (no float) so Go and Python produce byte-identical results: bytes = int_part*scale + frac_as_int*scale / 10^len(frac) (integer/floored). 1.5GB -> 1*G + 5*G/10 = 1610612736 = exactly 1536MB. Mirror in both languages + their tests; update the aira_mem marker docstring + the core.go ArgSpec size descriptions + skill example. Keep integer inputs + allow_zero behaviour identical. Deploy: binary rebuild+swap (Go parser in-binary; Python governor re-extracts from the embed on next --delegate-ram run); confirm whether --bytes is parsed client-side (no daemon restart) or daemon-side.
