Field data (various' BL-875 merge-gate engine leg, 2026-08-30): a fresh -n auto suite BLANKED with the AIRA-11 signature (exit 5, 'no tests ran in 1.58s', collection abort) DESPITE both AIRA-11 (ionice best-effort-7, banner-confirmed) AND AIRA-14/Slice-1 (cpu-weight aging, banner-confirmed cpu-weight=aging). The blank is pure PRE-PLUGIN execnet bootstrap (interpreter spin-up + imports), which runs BEFORE pytest loads the aira_xdist_governor plugin. Consequence: NEITHER Slice-1 (cpu.weight aging) NOR Slice-2 (the daemon active-set EXECUTION scheduler) can DIRECTLY gate it — Slice 2 helps only INDIRECTLY by bounding steady-state execution workers to free CPU for a fresh bootstrap. That covers the 'one fresh suite amid steady-state load' regime but NOT the 'multiple suites simultaneously cold-starting' regime (all bootstrapping at once, before any reaches the execution gate). The real fix for the simultaneous-cold-start regime is a WHOLE-SUITE bootstrap-admission: gate 'aira confine -- pytest' STARTS (not per-test) so only ~ncores/n_workers suites bootstrap concurrently. Open questions: where to gate (confine admission already exists for RAM — extend to a CPU-bootstrap slot?), how to size (a suite's bootstrap needs ~n_workers cores briefly), how to avoid deadlock/starvation (a suite must eventually bootstrap), fail-open when the daemon is down.
