`aira <verb> --help` is refused as a malformed option in twelve separate argv parsers, `-h` is swallowed as a positional, and an unknown option gets no did-you-mean outside confine
**kind** bug · **severity** P2 · **closes** RANT-7, RANT-20 (`--help` half)

**Why this is not T4** (stated so nobody re-merges them): everything here is decided in `cmd/aira/main.go`'s hand-written argv parsers, **before** `core.Do`, against a per-verb option-**name** vocabulary (`main.go:759-799`) that never reads `ArgSpec`. T4 changes `(*Core).Do` and operates on `ArgSpec.Enum` **values**. No line changed by one is read by the other.

**SYMPTOM.** `aira rant --help` → `option --help requires a value` (`main.go:730`, no error code; surfaced as `E_SELECTOR_INVALID` by the `E_INTERNAL` remap at `main.go:170-172`). `aira confine --help` → `E_CONFINE_ARGUMENT_INVALID: option --help is not valid for confine management` (`main.go:1287`) — the verb every agent types, reached because `parseConfineArgs` routes any argv with no `--` straight to the management parser, so a fix applied only to the generic body leaves it broken. `aira git --help`, `aira install --help`, `aira run-log --help`, `aira time --help` each answer differently again. `aira rant --tags x` → `option --tags is not valid for rant` (`main.go:811`) with no `did you mean --tag`, though `allowed[verb]` is in hand one line above and `optionDidYouMean` (`cmd/aira/option_suggest.go:75`) is already generic over any vocabulary — wired at exactly one call site, `main.go:897`. The reporter lost two rants to `--refs` before noticing. And `aira help rant` ignores its argument and dumps ~50 verbs.

`-h` is worse than unhelpful: it does not start with `--`, so `main.go:713-715` files it into `positional`, and for `create` the first positional is the required `title`. **Whether that allocates an ID is UNEVALUATED and must stay so — do not probe it; a stray probe already burned AIRA-200.** That risk is why this is P2 rather than P3.

**ROOT CAUSE.** `--help` is intercepted only as `args[0]` (`main.go:132`); `-h` nowhere. `parseArgs` (`main.go:675`) delegates to eleven sub-parsers before its own generic body — twelve vocabularies, twelve sentences, no single site. `cmd/aira/main.go` holds at least eight independent `strings.HasPrefix(arg, "--")` loops. **Dead code found while verifying:** `main.go:727-728` and `:806-808` branch on `verb == "git"`, but git is delegated at `main.go:706-708` and never reaches the generic body — delete both or the next reader will believe git's refusals come from there.

**PROPOSED FIX.** (1) Intercept `--help`/`-h` **once**, ahead of all twelve parsers, for a known verb, and render that verb's row from the existing `Core.Help()` data (verb, usage, summary — no new renderer). Intercept only before the first bare `--` separator so `aira confine -- mytool --help` still passes it through untouched; this is load-bearing. Make `aira help <verb>` do the same instead of ignoring its argument; refuse an unknown verb by name. (2) Append `optionDidYouMean(name, keysOf(allowed[verb]))` at `main.go:806-812` exactly as `main.go:897` does — additive clause, unchanged sentence, and because the suggestion vocabulary **is** the acceptance table, a suggestion can never name a refused option. (3) Give `main.go:730` and `main.go:811` stable error codes instead of leaning on the `E_INTERNAL` remap; CLAUDE.md requires stable codes and these two have none.

**Do not** add `tags`/`refs` to the `allowed` row without folding them to the canonical `tag`/`ref` at the `main.go:748` branch: `buildRequest` reads `options["tag"]`/`options["ref"]`, so an allowed-row-only alias makes `--tags a` **succeed with the tags silently dropped** — converting a loud exit 2 into exactly the silent loss the rant complains about. The in-tree precedent (`--label` → `labels`, `main.go:733-737`) folds and leaves the allowed row canonical.

**HOW TO TEST.** Table-driven over one verb per parser family (rant, run-log, run, time, git, install, `confine` with no delimiter, `confine ... -- cmd`, drain, worker-admit): each `--help` renders that verb's usage and exits 0. The `confine`-with-no-delimiter row is the one that catches a fix applied only to the generic body. `aira confine -- printf '%s' --help` must still pass `--help` to the child — a naive "scan all of argv" fix passes the first test and fails this. `create -h` must not reach the handler with `title == "-h"`. `rant --tags x` names `--tag`; `rant --zzz x` gets **no** suggestion (the never-invent rule at `option_suggest.go:16-20`). `aira help list` returns only list's entry.
