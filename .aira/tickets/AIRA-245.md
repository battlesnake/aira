## Triage 2026-10-12 (goal: clear remaining known issues)

**Disposition:** retired. **State on master v0.34:** still-open.

Every proposed fix adds admission machinery on a correctness-critical path (two-loop work) to guard a pathological, operator-visible case that already degrades safely on one path and warns on the other. Options: (1) per-parent worker-headroom reservation, which changes the ledger charge model and over-reserves in the common case; (2) a concurrent-parent count limit, which is policy/judgement, not a primitive; (3) an all-parents-blocked detector, which needs a new waiter-state analysis in the evaluator and still needs a policy for what to do on detection. All conflict with 'primitives not judgement' and 'keep the primitive + document the gap'. The greenfield minimum is the status quo: fair FIFO admission, bounded fail-open for confine-reserve, a visible stderr notice for aitest. Close as accepted gap; if anything, add one sentence to the admission/delegate-ram docs naming the over-subscription case and the remedy (`aira confine --list`, then `--kill` one parent). Reopen only if a real CI gate (deploy's per-leaf self-confine architecture) is observed wedged.
