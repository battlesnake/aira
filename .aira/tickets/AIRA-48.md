`TestRewriteResolverMatchesInstalledGitFixtures` (internal/gitremote/rewrite_fixture_test.go) shells out to git via runGit/runGitOutput, scoping every call to an isolated t.TempDir() fixture with "-C root". That scoping alone is not sufficient: git sets GIT_DIR (and friends) unconditionally in the environment of every hook invocation (pre-push, pre-commit, ...), and exec.Command inherits the parent process's environment by default. When this test's process runs from inside such a hook, the inherited GIT_DIR silently overrides "-C root", and every git subprocess the test spawns operates on the REAL repository the hook is running against instead of the fixture.

DISCOVERED 2026-09-02: a `git push` on the aitest branch triggered .githooks/pre-push -> make ci -> unconfined `go test ./...`, and this test's fixture git calls corrupted the shared repository: wrote config sections and commits from unrelated fixture test cases directly onto real refs/heads/* and the shared /home/mark/claude/aira/.git/config, deleting most of the tracked tree on the pushing branch and clobbering global config shared by every worktree of this repo. Recovered via targeted `git config --file` repairs to the shared config and `git update-ref` + `git reset --mixed` (not --hard, since the working tree was independently confirmed untouched — the corrupting commits only rewrote git objects/refs/index, never checked-out files) to the affected branch ref.

FIX: strip GIT_-prefixed variables from the environment given to every fixture git subprocess via a new sanitizedGitEnv() helper, wired into both runGit and runGitOutput. Verified via `aira confine -- go test ./internal/gitremote/...` (all tests pass) followed by re-checking the shared .git/config and affected branch refs were unchanged after the confined run.

This was referred to as "AIRA-46" in the fix commit/PR at the time, but no ticket record was created then — this ticket is that record, created retroactively under the allocator's next real ID.

MERGED (2026-09-02, master via PR #1, squash commit `3c519b9`), standalone from the aitest work it was discovered during. DEPLOYED as part of the same binary swap + daemon restart as AIRA-47.

RESIDUAL RISK, not yet closed: the local pre-push hook's `make ci` always builds/tests against the shared /home/mark/claude/aira checkout specifically (its ROOT_DIR is derived from the hook script's own absolute, shared hooksPath, not the pushing worktree) — so the hook remains a live risk for ANY future push, from ANY worktree, until that shared checkout's own working tree is fast-forwarded to include this fix (a plain `git -C /home/mark/claude/aira pull --ff-only origin master`). A worktree-isolated session is structurally blocked from running that command against the shared checkout root — it needs the owner, or a non-isolated session, to run it once. A secondary, independent design issue worth its own look: the hook testing whatever the shared checkout happens to have checked out, rather than what's actually being pushed, is surprising and was itself part of what let this bug's blast radius reach beyond the fixture test's own tree.
