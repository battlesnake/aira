Declared closed enums are enforced by five incompatible copies and by none of them on the CLI/core dispatch path, so a wrong value gets a message naming neither the value nor the allowed set
**kind** bug · **severity** P2 · **closes** RANT-3 (mv half), RANT-24, RANT-28 (second half), RANT-20 (severity half)

**SYMPTOM.** `aira mv AIRA-4 in_progress` → `E_TRANSITION_INVALID: planned -> in_progress`, which reads as the status *graph* refusing a legal move when the fault is the token spelling. `aira rant "..." --severity P1` → `E_RANT_INVALID: severity is invalid` — no value, no set; reporters guessed a P-ladder because every other severity in AIRA is one. The same call over MCP returns a *different* code and sentence for the identical fault, still without value or set. Meanwhile `aira create --severity P9` names field, value and ladder, because AIRA-170 fixed tickets and only tickets.

**ROOT CAUSE.** `internal/core/core.go:523` — `(*Core).Do` resolves the spec and calls `spec.Run` with **no** enum validation, although 41 dispatch-table args declare `ArgSpec.Enum` (all via `stringSpec`'s variadic tail). The CLI reaches core only through `Do`, so on the CLI face all 41 declarations are inert. Five incompatible enforcement copies exist instead: `internal/domain/ticket.go:189` `invalidFieldError` (field + value + set — the only good one, ticket-only, callers `:207/:210/:213`); `cmd/aira/mcp.go:601-606` (generic, names the argument only); `cmd/aira/tui_palette.go:202-203` (generic, names field and set but **not** the offending value); `internal/install/install.go:451,456` (hand-written, duplicated at `:612,615`); `internal/domain/rant.go:150` (field only). And `internal/store/mutate.go:58` calls `ValidateTransition` *before* anything validates the status token, so an unknown token can never reach the good message.

**PROPOSED FIX.** Export one `domain.InvalidEnumValueError(field, value, allowed)` shaped like `ticket.go:189` and call it from **one** generic check in `(*Core).Do`, iterating `spec.Args` before `spec.Run`; every face inherits it. Delete `tui_palette.go:202-203`; make `mcp.go:601-606` emit the identical sentence (keep `E_ARGUMENT_INVALID` if that code is face-stable). In `mutate.go:58`, validate the target status against `domain.AllowedStatusStrings()` **before** `ValidateTransition`, so `E_TRANSITION_INVALID` is reserved for a legal-but-forbidden edge. Then delete `rant.go:150` and fold `install.go:451,456` into the shared helper.

**TWO HARD CONSTRAINTS — a fix skipping either ships a regression.**
- **(a) Case folding.** Twelve of the 41 enums are the `subverb` positional and every one is lower-cased by its handler before the switch (`core.go:781, 1008, 1073, 1156, 1217, 1251, 1311, 1389, 1572, 2177`); `rant.go:148` lower-cases rant severity; `testreport.go:110` lower-cases `format`. `aira rant LS`, `--severity Annoyance` and `--format GO-JSON` all work **today**. The checker must trim and fold and write the canonical value back so handlers can drop their own folds. This also means an acceptance test asserting the message echoes `"P1"` fails against a correct implementation unless the raw pre-normalisation value is captured — capture it (echo what the caller typed).
- **(b) Blast radius is not uniformly bounded by MCP.** For the 29 non-subverb enums the CLI merely catches up with MCP. But the 12 `subverb` enums are never caller-supplied on MCP (`mcp.go:471` injects them from the binding) and `install`'s two enums sit on a verb with no MCPTool. Those 14 have no precedent: check each declaration by hand against its handler for values the handler accepts but the declaration omits, and **widen the declaration rather than narrowing the CLI**.

Note for the body: finding *severity* is not a fourth hand-maintained ladder — `finding.go:183` reuses `validSeverity`; the finding work is purely splitting one collapsed message into two arms. Only rant severity has the three-place copy (`rant.go:34-36`, `core.go:753`, the SQLite `CHECK` at `store.go:966`) — pin that with a test asserting the three agree rather than making the DDL text dynamic.

**HOW TO TEST.** `mv` with `in_progress` names the token and every allowed status (today: `E_TRANSITION_INVALID: planned -> in_progress`). Rant severity `P1` names `P1` and `papercut, annoyance, blocker`. **`TestEveryDeclaredEnumIsEnforcedAtDispatch`** — walk the table, submit `"__not-a-member__"` for every enum-bearing arg, require a refusal naming arg/value/set; fails today for all 41 and cannot be satisfied by fixing one verb. **`TestUpperCaseEnumValuesStillAccepted`** — write it before the dispatcher check, watch it pass, keep it green. And one asserting the refusal is byte-identical across the CLI and MCP faces.
