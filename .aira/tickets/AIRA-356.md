Owner 2026-11-19: 'adjusting the booking of long-running tasks to be closer to their actual size'. Today bookings run 2-3x real use (measured: real slice use median 0.345 of bookings, AIRA-354 replay s6) and a booking is held for the whole job. aira confine --resize (AIRA-312) already lowers a running job's ledger booking by hand (ledger only; memory.max unchanged; OOM-steering budget drops with it; a daemon restart re-books the full pin). Question: have the daemon do it automatically for jobs that have run long enough, and how does that compare with AIRA-354 (bounded ledger overbooking, no per-job change)? Needs a replay of real long-running jobs: booking vs peak-so-far over time, and the regret rate (a job later exceeding the lowered booking). Spec comparison first; correctness-critical (host memory exposure), two-loop.
