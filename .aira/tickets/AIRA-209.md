Registry discovery re-logs every dead-root breadcrumb every ~33 s forever (97.5 % of the daemon journal) and burns 3 git forks + 75 ms of retry sleep per dead root per pass
**kind** bug · **severity** P2 · **closes** RANT-16 (and RANT-12's reviewer finding)

**SYMPTOM.** Measured live in a 10-minute window: 918 of 942 daemon journal lines (97.5 %) are one message — `registry discovery skip project ... root "...": E_NOT_PROJECT`. The remaining 24 are 18 aggregate lines and 6 real `slice ceiling throttled (enforce)` lines, buried at 1:150. The journal is the **only** observability surface for the watchdog, slice-ceiling and OOM-steer subsystems. 26 distinct dead roots; 51 records of 771–784 point at them. The message also embeds a literal `E_NOT_PROJECT`, false-positiving the `E_[A-Z]{3,}` greps agents are told to run. Direct measurement fingerprints the fork cost: consecutive skip lines are spaced ~80.4 ms = 3 × 25 ms sleep + 3 git forks, ~153 forks and ~4.0 s per pass, ≈400k wasted git forks/day on the box whose whole purpose is contention control.

**ROOT CAUSE.** `internal/daemon/discovery.go:46-49` does `skipped++; logRegistryDiscoverySkip(entry, err); continue` and sets no latch; the only latch (`discoveryFailed`) is set solely in the `storeForScope` branch. `logRegistryDiscoverySkip` (`discovery.go:85-87`) is a bare `log.Printf` — and there is no log-level concept anywhere in `internal/daemon`, so "demote to debug" would mean inventing one. The fork cost comes from `discoverGitRoot` → `gitValue` (`internal/app/project.go:764-774`), which retries every failure three times with a 25 ms sleep; a permanently absent directory always exhausts all three. **Accumulation mechanism (corrected):** the breadcrumb writer is `Store.Register` (`internal/store/store.go:1970-1992`) via `registerOnceFn` inside `NewScope` — i.e. **any** aira command opening a scope in any checkout. It is not `aira worktree register` (that verb writes only the `worktree_bindings` table), so an opt-in "forget" verb cannot keep up with it and should not be proposed as the follow-up.

**PROPOSED FIX.** (1) `os.Stat(entry.Root)` before forking; on ENOENT count as skipped and skip `discoverProjectAt` — but **route that branch through the transition logger with a synthesised error**, or a dead root logs zero times and contradicts test 1. (2) Log on transition: a `lastDiscoverySkip` map keyed on `WorktreeID + "\x00" + Root` (duplicate breadcrumbs can carry the same worktree at different roots), logging only when the error string for a key changes, plus one recovery line. 51 lines/pass becomes 26 one-time lines. (3) Leave the aggregate accounting line untouched.

**HARD CONSTRAINTS.** The retry must **not** be latched — `discovery_test.go:247 TestRunRegistryDiscoveryRetriesTransientEntry` asserts a transiently-failing root is retried and eventually covered (its root really exists, so a stat short-circuit does not weaken it). **And a design fork the ticket must resolve, or it ships a porous test:** `TestDiscoverRegistryPassSkipsBadEntriesAndGuardsIdentity` (`discovery_test.go:134-181`) uses fabricated non-existent roots `/missing` and `/reused` driven through an injected `discoverProject` hook; a stat placed in `discoverRegistryPass` short-circuits `/reused` so the identity-mismatch branch is never reached and the test passes **vacuously**. Either (a) stat before the hook and convert those fixtures to real directories, or (b) stat inside `discoverProjectAt`'s production-only branch — which leaves existing tests intact but makes the proposed hook-counting test unimplementable and needs a different observation seam.

**OUT OF SCOPE, keep the primitive.** Auto-pruning ENOENT breadcrumbs is **not** proposed: `store.go:1987-1988` states why the breadcrumb is written before the DB transaction ("a stale breadcrumb is recoverable evidence; a DB row without a breadcrumb is not recoverable after DB loss"). **But cite AIRA-88 explicitly** (done, 2026‑09‑04): it decided "registry.jsonl stays append-only, no compaction" on the strength of "131 lines / 39 KB … needs no bound this decade", and the file is now **784 records / ~239 KB — six-fold growth in five days** (cumulative through 2026‑09‑04 is exactly 131, matching AIRA-88's own measurement). The decision is not open; its premise has expired, and the owner should be told.

**HOW TO TEST.** `TestDiscoveryLogsAMissingRootOncePerTransition`: three passes over one removed root → exactly one skip line, `skipped == 1` every pass (current code emits three). `TestDiscoverySkipsGitDiscoveryForAnAbsentRoot`: hook counter is 0 after two passes (current code calls it twice). `TestRunRegistryDiscoveryRetriesTransientEntry` must pass unmodified.
