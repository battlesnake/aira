Found in the v0.32 plan review of AIRA-175. Rebuild re-points a still-allocated TICKET row at the scanned file (store.go, guarded UPDATE allocations ... state='allocated' AND path<>?), but Rebuild's requirement loop (store.go, requirement upsert) never updates the allocation's path. A requirement row CAN stay allocated beside its file (the crash window between the file write and markRequirementMaterialised; TestCheckResolvesCrashWindowRequirementAllocation covers it in the allocating worktree). Whether such a row resolves from another worktree after the allocating one is removed is unevaluated; the missing re-point is a possible E_ID_UNRESOLVED false-fail for a requirement file present in the checking worktree. Not reproduced (needs a crash plus a removed worktree). Fix if wanted: mirror the ticket loop's guarded re-point UPDATE into the requirement loop, with a test like the AIRA-175 pin.
