Owner request 2026-11-16: allow the admission queue priority of AIRA-340 (`aira confine --priority high|normal`) to be specified or overridden by an environment variable too. Precedence: an explicit --priority flag, else AIRA_CONFINE_PRIORITY (high|normal, exact; unset, empty or whitespace-only is absent; anything else is refused E_CONFINE_ARGUMENT_INVALID naming the variable), else normal. Read by the confine launch client only and STRIPPED from the confined command's environment, so a nested aira confine, aitest worker or make recursion does not inherit a high request (unlike AIRA_CONFINE_OWNER, which names a session and propagates on purpose). The repo's pre-commit hook asks for high by setting the variable only when the caller has not (${AIRA_CONFINE_PRIORITY:-high}), so `AIRA_CONFINE_PRIORITY=normal git commit` overrides it; the hook's old-client help probe is deleted. Client, hooks, skill text only; no daemon or protocol change.
