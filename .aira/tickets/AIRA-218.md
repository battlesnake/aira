A newer binary's additive ledger field is classified as `E_JOURNAL_CORRUPT`, and the schema check that exists for exactly this is unreachable
**kind** bug · **severity** P3 · **closes** RANT-23 (classification half) · *the weakest of the new tickets — see the note*

**SYMPTOM.** Between 2026‑09‑07 23:43 and 2026‑09‑08 02:53, `aira reconcile` and `aira check` failed machine-wide with `E_JOURNAL_CORRUPT: invalid run ledger record`, exit 4, so an agent could not use `aira check` to see the ticket-file defect it was fixing. It was never corruption: `b6b56cb` added `Containment ... json:"containment,omitempty"` at `internal/runner/types.go:163`, the live shared ledger contains `"containment":"advisory(ci-shim…`, and `internal/runner/ledger.go:309` decodes with `DisallowUnknownFields()`. The run ledger is common-dir state shared by every worktree while each worktree runs its own build, so mixed readers are the normal condition here.

**ROOT CAUSE.** Three things, one of which is new: (a) an unknown field is folded into the integrity family at exit 4, and `ledger.go:384-386` already names the newer-binary case in a comment while still classifying it as corruption; (b) **`const ledgerSchema = 1` exists at `internal/runner/ledger.go:25`** — the ledger-side twin of `ProtocolVersion`, which the project bumps with ritual — and AIRA-129 changed the record shape and bumped nothing; (c) **the schema check is unreachable**: `ledgerRecordDefect` evaluates `case decodeErr != nil` before `case event.SchemaVersion != ledgerSchema`, and `DisallowUnknownFields` fires first, so even a bumped constant would still report "payload did not decode".

**PROPOSED FIX.** Weigh the cheap option first and say why it is or is not enough: a **ledger-schema bump discipline** (bump `ledgerSchema` when the record shape changes; a test asserting the constant moves with the struct) plus a lenient-then-strict two-pass decode so the schema arm is actually reachable. If a distinct code is added, **name it for what is known** — this binary does not recognise field X; the ledger was written by an aira with a different record schema; reinstall is the likely remedy — never "written by a NEWER aira", which an unknown field does not establish (a branch build with an experimental field produces the identical signal). Do **not** relax `DisallowUnknownFields`; strict decoding is what makes genuine malformation detectable. If a new code is introduced it must join the AIRA-172 degrade list so the dimension degrades rather than failing the verb. **And do not hand-wave the classifier**: `encoding/json` exports no sentinel for this, so the ticket must choose between prefix-matching the literal string and the two-pass decode, and the two-pass version is the non-fragile one.

**HOW TO TEST.** `internal/runner/ledger_corrupt_diagnostics_test.go` already builds synthetic ledgers in `t.TempDir()`: frame a record carrying a future field and assert the new code and message, and that the other four defects still return `E_JOURNAL_CORRUPT`. In `internal/store/check_run_ledger_test.go`, assert a schema-ahead ledger grades `run-ledger` unevaluated and leaves every other dimension exactly as a healthy ledger grades it.

**Note for the owner (why P3, and a fair case for wont-fix).** AIRA-172 already fixed the blast radius, and AIRA-145 already puts the offending field name in the message (`encoding/json`'s own text names it). What remains is only the word "corrupt" and the exit class — and with T2a landed, diagnosing this takes seconds. If the owner prefers "keep the primitive, document the gap", the honest alternative is: record the schema-bump discipline in the ledger's own doc comment, leave the classification alone, and close RANT-23's classification half wont-fix. **Coverage gap to record either way** (critic §6.5): the AIRA-145 coordinates were added to the **decode** site only. The replay-integrity sites (`ledger.go:211-225`, `:461-495`) and `internal/store/gate_audit.go:69-83` — roughly 13 emission sites — still emit `E_JOURNAL_CORRUPT` with no path, record index or offset, so RANT-22's literal complaint recurs verbatim if a replay check fails rather than a decode.
