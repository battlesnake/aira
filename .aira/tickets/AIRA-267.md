Owner (2026-09-19): "ticket it and build it" — the caller can already give a task a name via `aira confine --name <label>`, but it doesn't reach the CI trace/dump artifacts as a structured field, so CI can't attribute per-task telemetry (peak-rss/cpu) to a named task. Follow-up to the AIRA-265/266 owner-attribution work (name is the per-TASK axis; owner is the per-SESSION axis).

## Requirements (deploy = the CI-trace consumer, confirmed 2026-09-19)
deploy's CI gate already archives (a) the per-job confine TRAILER line (parsed by fastest_ee/tools/quality/pytest_timeout_classify.py, which tokenises key=value facets: terminated-by=/cap-source=/peak-rss=) and (b) `aira confine --dump` JSONL (aira-confine-dump.jsonl). Both are per-SCOPE = per-leg/task = exactly the granularity --name maps to. deploy wants a machine-readable `name` field on BOTH; the TRAILER facet is the higher value (it attributes peak-rss/cpu to a NAMED leg — answers "is leg-<suite> a genuine long pole or poor worker-packing?"). deploy is wiring --name into its ~8 launch sites + an enforcement test, so named scopes will exist.

## Design (grounded via workflow wf_e1bcc0f2-6af, 2026-09-19)
The confine name today: parsed → `ConfineRequest.Name` (confine.go:537) → normalised (empty→"job", validated `[A-Za-z0-9._-]` ≤100 chars, confine.go:1160/1192) → embedded as the first field of the scope-id `CONFINE-<name>-<pid>-<stamp>[@owner]`. It surfaces in `--list` (decoded from the scope-dir name), the daemon waiter, and the scope-id — but NOT as a structured field in the trailer or dump.

1. **TRAILER `name=` facet (highest value).** Add `Name string` to `ConfineStatus` (confine.go:249); populate `result.Status.Name` from the normalised name at the assembly sites — live `confineWithDeps` (normalizedName at confine_linux.go:479, request.Name at :484), ci-shim `confineShim` (confine_shim_linux.go), and the detach-record projection (confine_detach.go:393; record.Name already available, and the detach HEAD line already renders `name=` at confine_detach.go:362 — the convention to match). Render `name=<label>` in `FormatConfineStatus` (confine.go:920+) as an always-rendered facet, empty→`name=unevaluated` (honesty discipline). Safe to append unescaped: validateConfineName forbids spaces/`=`/`:`. Emission sites: confine_linux.go:1463, confine_shim_linux.go:515, confine_detach.go:393.
2. **`--dump` `name` field on WAITER rows.** Add `Name string \`json:"name,omitempty"\`` to `ConfineDumpWaiterRow` (confine_dump.go:105); set `Name: waiter.name` in the waiter-row walk (ci_dump.go:215-220). `waiter.name` is already in scope (admit.go:161) and is parity-checked against the scope-id's embedded name at admit (admit.go:3028), so no drift. NOT on `ConfineDumpAdmissionRow` (signature-keyed persisted history, no per-job name — adding one would fabricate, violating confine_dump.go's honesty rule) nor `ConfineDumpQueueRow` (per-slice aggregate).

## Explicitly OUT of scope (simplify pass + deploy)
- **NO `AIRA_CONFINE_NAME` env var.** A task name DIFFERS per task; an env var set on a launch command would propagate into ALL nested `aira confine` calls and give them the SAME name — fighting per-leg naming. deploy (sole consumer) explicitly does not want it; the `--name` flag is the correct mechanism. (This drops the env-var half of the original offer — a deliberate reduction.)
- **Aitest AIRA-259 trace structured `confine_name` arg: DEFERRED** (deploy ranked it lower; the name is already present as a substring of the trace's `process_name` label. A future nice-to-have: a structured `confine_name` in the trace span args / pool-report, sourced by publishing the name via AppendAitestChildEnvironment rather than re-parsing the scope-id).
- The `runs` telemetry (RunRecord) has a Label field but no confine-name path; NOT bridged here (confine --name ≠ aira run --label).

## Build decisions (2026-09-19, Opus + stronger-reviewer pass)
- **Facet placement: `name=` renders as its own token right after `slice=`, before `containment=`** (identity leads, matching the detach HEAD line convention `scope= name= owner=`). deploy's classifier tokenises key=value, so position is free for it; the only in-repo positional consumer is our own exact-match regression `TestFormatConfineStatusUnchangedWithoutContainer` (container_confine_linux_test.go:443), updated to expect `name=unevaluated` in `base`. The Python-side reader (pytest_aitest_topology_e2e_test.go:861) only `HasPrefix`es `"confine: slice="`, which survives. No SKILL text quotes a literal trailer prefix.
- **`name=unevaluated` arm reachability** (it is NOT dead code): the mainline flow defaults empty→"job" via normalizeConfineIdentity BEFORE Status.Name is set, so `name=unevaluated` renders only on (i) early-abort trailers that return before identity validation (confine_linux.go pre-:479 — nothing ran, so no name is correct) and (ii) any hand-built ConfineStatus with no Name (the regression test above). Pinned directly by the FormatConfineStatus render test's empty case.
- **Detach path CONFIRMED to carry the name** (not a pre-populate copy): confine_detach_linux.go:751-752 does `result, _ := Confine(ctx, request); status := result.Status; record.Status = &status` — it snapshots result.Status AFTER the full Confine() runs the `result.Status.Name = normalizedName` wiring (confine_linux.go:490), so the persisted detach record and its trailer (confine_detach.go:393) render `name=` correctly.
- **End-to-end emission pinned**: TestShimConfineWiresTheNameOntoTheStatus asserts the facet in the ACTUAL emitted stderr (the supervisor's written trailer), not a test-reformatted line — so a mutation emitting a fresh `ConfineStatus{}` at the shim emission site (confine_shim_linux.go:515) reds it, closing the last hop the assembly-only assertion missed.
- **Daemon-restart decision: v0.22 ships CLIENT-ONLY.** The trailer `name=` half is client-side and works on install. The dump `name` half is daemon-served; the live daemon stays at its current version, so `--dump` waiter rows omit `name` (omitempty) until the daemon is next restarted onto v0.22. This is deliberate: deploy is still wiring `--name` into its launch sites, so no named scopes exist to attribute in the dump yet — a restart now would blip live peer legs for a half with no ready consumer. The dump half converges on the daemon's next restart (naturally, or a heads-up'd restart when the box is quiet). deploy told explicitly on release.
