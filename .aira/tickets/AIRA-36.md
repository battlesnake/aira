Found 2026-09-01 via the kill-rate monitor investigation (the OOM burst was benign contained self-OOM; the dig turned this up). PREREQUISITE for aitest's nested-scope model.

BUG: the #72 orphan-scope reaper (`internal/daemon/confine_reaper.go` → `runner.ReapOrphanedConfineScopes`) removes an orphaned empty scope with a SINGLE-LEVEL `unix.Unlinkat(AT_REMOVEDIR)`, which the kernel refuses on a NON-EMPTY cgroup. So any confine scope that has leftover CHILD cgroups when its supervisor dies (crash / OOM-kill / SIGKILL — paths that never run cleanup) orphans the WHOLE TREE permanently. Verified live: 32 lingering dead scopes, 31 were aitest `.aitest-worker-test`-nested trees (dead supervisor, 0 procs, up to 46min old) the reaper could never sweep; 0 plain-leaf orphans (the reaper handles those fine — it's specifically the nested case). Recursive `rmdir` child-then-parent cleans them trivially (proven; manually cleaned all 31 with a per-node dead-supervisor+empty-subtree liveness gate, correctly skipping 2 with live supervisors).

WHY LOAD-BEARING FOR aitest: aitest's outer scope ALWAYS has `.aira-supervisor` + N `.aira-worker-*` children at run death, and its design (spec §3.6) treats worker/supervisor OOM-death as NORMAL — those paths never self-clean. aitest confirmed (2026-09-01): the reaper must be the authoritative backstop, not supervisor self-cleanup (which is best-effort on graceful exit only). Without this, every crashed aitest run litters the slice permanently → unbounded dead-cgroup-tree accumulation.

FIX: make the reaper subtree-aware — reap empty+dead DESCENDANT cgroups deepest-first before the parent, applying the same #72 positive-proof gates per node (all-descendants-empty + supervisor-dead(ESRCH) + age≥2m + !Pending + no live admit lease). Keep the parent-fd-anchored AT_REMOVEDIR (kernel rmdirs only genuinely-empty cgroups → race-safe: a proc appearing mid-sweep just fails that node's rmdir, no force). Correctness-critical → full two-loop. relates AIRA-30 (aitest Slice 1 dependency), #72 (the reaper being extended), #20/#70 (scope machinery). Owner-aware; driving 2026-09-01.
