VETTED DESIGN (2026-09-14, 3-critic adversarial panel — simplify/correctness/grounding — vs the real confine code). Owner steer (via speed): SIMPLE and CLEAN, do not over-engineer.

FINDING: my initial DAEMON-side cohort sketch was OVER-ENGINEERED. Grounded blockers: the admission socket it wanted to reuse is 1-bit LIVENESS in both directions — the daemon learns "socket closed", never the exit code (watchPeerEOF reads exactly 1 byte, admit.go:1902), and it cannot push a cancel reason post-grant (the client reads ANY inbound byte as "daemon restarted" -> reconnect/re-declare loop, lease_keeper). A daemon primitive that TRIPs on exit code + PUSHes attribution = rewriting the liveness-correctness core across 4 lease-bearing call sites, for what is (by the design's own concession) an optimization, not a correctness property.

RECOMMENDED: launcher-side cohort, ZERO aira change. merge_gate.sh launches the N legs as `aira confine --name … -- <cmd>` children of ONE parent; the parent wait()s them (it already learns every exit code directly — the holder has the channel). On first non-zero exit, the parent SIGTERMs the other legs' `aira confine` PIDs:
- running -> supervisor cgroup.kills its scope -> terminated-by=supervisor-signal:SIGTERM (honest, already stamped)
- queued/late -> SIGTERM aborts the admission wait via the existing S13 peerCtx path -> ran=no, reserve released. So cancel-on-admission (req #3) is FREE.
The parent stamps cohort-cancel + trigger=X into the per-leg result records the consumer reads anyway; the trigger leg keeps its own non-zero verdict. Meets all 3 of speed's reqs IF his classifier keys on (supervisor-signal:SIGTERM | ran=no) + a launcher-recorded cohort-cancel:trigger, rather than a native aira trailer token.

PIVOTAL Q (2026-09-14): does merge_gate.sh's classifier need a native terminated-by=cohort-cancel token from aira, or is launcher-owned classification enough?

RESOLUTION (2026-09-14, speed): LAUNCHER-OWNED CLASSIFICATION SUFFICES — ZERO aira change. speed's classifier keys entirely on trailers that already exist per-leg: a running leg the parent SIGTERMs -> terminated-by=supervisor-signal:SIGTERM (mg_leg already reads+classifies this, BL-1037); a queued leg whose admission aborts (S13 peerCtx, reserve released) -> ran=no; plus a launcher-recorded cohort-cancel:trigger=X stamp the parent writes into each cancelled leg's own record. No native aira trailer token needed. My rejection of the daemon-side design was confirmed correct: the admission socket is 1-bit liveness both ways, so making it carry an exit code / push a cancel reason would mean rewriting the liveness-correctness core for an optimization the launcher can own for free.

## REOPENED + FINALIZED DESIGN — owner directive (2026-09-24), BUILDING
The owner directly authorized building the NATIVE daemon primitive, in a SIMPLER shape than the per-cohort design above: a single flag, CI-mode-only, slice-wide.

**`aira confine --fail-fast`** — one boolean flag marking a task as a fail-fast trigger.
- **Safety gate (THE load-bearing invariant):** the daemon acts on a trip ONLY in shim (ci-shim) confine mode (`s.shimMode()`). The shared box daemon is Real cgroups → a trip there is a NO-OP (logged, ignored), so `--fail-fast` can NEVER kill cross-session jobs on the box. The gate lives in the DAEMON, not the client. This is the confirmed answer to "how is CI mode set up": the CI daemon is explicitly `aira install --ci=shim` (or `AIRA_DAEMON_CONFINE_MODE=shim`), recorded in the install-mode record and read as shim mode — shim mode IS the explicit CI configuration (default is Real).
- **Report:** the daemon can't see exit codes (1-bit liveness socket), so the `--fail-fast` CLIENT, on its task's non-zero terminal outcome, sends a "trip" to the daemon over a fresh management connection (new RPC, modelled on `confine --kill` dispatch), carrying the trigger's `--name`.
- **Trip (shim-mode only), under queue.mu:** set a slice-wide `failfastTripped` flag; then (a) STOP ADMITTING — the admit path refuses new admissions with new code `E_ADMIT_FAILFAST_TRIPPED` and wakes current waiters with that refusal (existing admitRejected/close(grantedCh)/peerCtx path) → ran=no, reserve released; (b) KILL RUNNING — SIGTERM each activeConfines supervisor PID (existing pidfd/kill), each supervisor forwards to its task's process group (kill(-pgid), shim path) so the whole tree dies, victims stamped `terminated-by=failfast-cancelled:trigger=<name>` (distinct from OOM-137 / real failure / normal / supervisor-signal:SIGTERM, for deploy's classifier).
- Slice-wide (owner-confirmed); tripped persists for the daemon run. Image-boot's `docker buildx bake` is a documented exception (buildkitd double-forks out of the process group → survives a pgid signal; mitigation is per-leg wiring, not a flag change).

Built via the two-loop (Opus fork builds with full design context; independent adversarial review + mutation-verify — esp. the box-safety gate goes RED if the shim-mode guard is removed). deploy notified when the release ships (owner instruction).

## DONE — shipped v0.26 (2026-09-24, merge bebbbf9, PR #180). AS-BUILT deltas from the design above:
- **Sweep signal is SIGUSR1, not SIGTERM.** SIGTERM stays reserved for operator/Batch teardown (→ `terminated-by=supervisor-signal:SIGTERM`); SIGUSR1 is the fail-fast teardown, caught ONLY by ci-shim supervisors (a real-mode supervisor keeps SIGUSR1's default action, so a stray SIGUSR1 on the shared box is never misattributed).
- **Victim stamp is BARE `terminated-by=failfast-cancelled`** — no `:trigger=<name>` suffix. The victim doesn't know the trigger; deploy's classifier identifies the trigger as the leg with a genuine non-zero verdict, victims by the `failfast-cancelled` facet.
- **An operator/Batch teardown of a --fail-fast leg does NOT trip** (a teardown is not a task failure). A genuine non-zero exit, OOM, crash or deadline does.
- **Refused queued leg:** `code=E_ADMIT_FAILFAST_TRIPPED` (exit 1) + `admission=failfast_tripped`, distinct from saturated.
- Two-loop found + fixed a P1 honesty bug (a sweep SIGUSR1 in the shim output-drain window falsely stamping an already-finished sibling); 16 mutations verified RED; make ci + -race green. Two-tenant/two-trigger concurrency is handled by the runEnded witness cut-off + sweep trigger-skip.
