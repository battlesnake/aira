VETTED DESIGN (2026-09-14, 3-critic adversarial panel — simplify/correctness/grounding — vs the real confine code). Owner steer (via speed): SIMPLE and CLEAN, do not over-engineer.

FINDING: my initial DAEMON-side cohort sketch was OVER-ENGINEERED. Grounded blockers: the admission socket it wanted to reuse is 1-bit LIVENESS in both directions — the daemon learns "socket closed", never the exit code (watchPeerEOF reads exactly 1 byte, admit.go:1902), and it cannot push a cancel reason post-grant (the client reads ANY inbound byte as "daemon restarted" -> reconnect/re-declare loop, lease_keeper). A daemon primitive that TRIPs on exit code + PUSHes attribution = rewriting the liveness-correctness core across 4 lease-bearing call sites, for what is (by the design's own concession) an optimization, not a correctness property.

RECOMMENDED: launcher-side cohort, ZERO aira change. merge_gate.sh launches the N legs as `aira confine --name … -- <cmd>` children of ONE parent; the parent wait()s them (it already learns every exit code directly — the holder has the channel). On first non-zero exit, the parent SIGTERMs the other legs' `aira confine` PIDs:
- running -> supervisor cgroup.kills its scope -> terminated-by=supervisor-signal:SIGTERM (honest, already stamped)
- queued/late -> SIGTERM aborts the admission wait via the existing S13 peerCtx path -> ran=no, reserve released. So cancel-on-admission (req #3) is FREE.
The parent stamps cohort-cancel + trigger=X into the per-leg result records the consumer reads anyway; the trigger leg keeps its own non-zero verdict. Meets all 3 of speed's reqs IF his classifier keys on (supervisor-signal:SIGTERM | ran=no) + a launcher-recorded cohort-cancel:trigger, rather than a native aira trailer token.

PIVOTAL Q (2026-09-14): does merge_gate.sh's classifier need a native terminated-by=cohort-cancel token from aira, or is launcher-owned classification enough?

RESOLUTION (2026-09-14, speed): LAUNCHER-OWNED CLASSIFICATION SUFFICES — ZERO aira change. speed's classifier keys entirely on trailers that already exist per-leg: a running leg the parent SIGTERMs -> terminated-by=supervisor-signal:SIGTERM (mg_leg already reads+classifies this, BL-1037); a queued leg whose admission aborts (S13 peerCtx, reserve released) -> ran=no; plus a launcher-recorded cohort-cancel:trigger=X stamp the parent writes into each cancelled leg's own record. No native aira trailer token needed. My rejection of the daemon-side design was confirmed correct: the admission socket is 1-bit liveness both ways, so making it carry an exit code / push a cancel reason would mean rewriting the liveness-correctness core for an optimization the launcher can own for free.
