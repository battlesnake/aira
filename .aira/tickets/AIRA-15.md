MECHANISM (code-grounded): the SLICE has memory.oom.group=0, so when the slice hits its own memory.max (64G) it does PROCESS-LEVEL OOM-kills (kills the highest-oom_score single process), NOT a scope-group-kill. Evidence: live aira.slice memory.events shows oom_kill=1909 (individual-process kills) + oom_group_kill=250. A capped neighbor's worker (e.g. various' -n8 engine worker, a big single process) gets killed as collateral; because the OOM is at the SLICE not the scope, the scope's own oom_kill counter doesn't fire -> the runner reports status=killed, not oom-killed (matches the report exactly). The capped 32G job was well under its 32G cap (~13%) -> killed externally, not by its own cap.

ROOT CAUSE = an UNCAPPED AIRA scope escapes BOTH containment layers: (a) admit.go:316 leaves the scope UNCAPPED when admission does not reach 'admitted' state -> no per-scope memory.max -> its actual RSS is unbounded -> it drives Sigma(actual) past the slice cap despite the reserve ledger (reserve != actual, the [[AIRA-12]]/[[AIRA-6]] class); (b) the watchdog EXEMPTS every AIRA component (watchdog.go:553 'if !cgroup.uncapped || hasAIRAComponent(path)' -> skip), trusting that AIRA scopes are self-capped -> it never kills the uncapped AIRA hog. Also the watchdog is MemAvailable-based (machine-wide), so a SLICE-INTERNAL OOM (slice at 64G while machine has ~14G MemAvailable free) doesn't trip it at all. So the 20.6G uncapped hog survives (29min) while the slice OOMs innocent capped jobs.

FIX DIRECTIONS (for the two-loop; owner steer + not rushed — correctness-critical containment): (A PRIMARY) NEVER run an AIRA confine scope uncapped in the shared slice — on non-admitted/estimate-unavailable, set scope memory.max to the granted reserve or a conservative default (or refuse to launch, like the uncapped-SLICE refusal). Then Sigma(actual) <= Sigma(scope caps) <= cap-headroom holds for ACTUAL, each scope's own oom.group=1 contains its own overrun, and no capped neighbor is collateral. This restores the #67 per-scope-containment invariant that the watchdog's AIRA-exemption ASSUMES. (B) the watchdog should treat an UNCAPPED AIRA scope as a valid target (it is the offender, not exempt) rather than blanket-exempting all AIRA components. (C) add a slice-internal-pressure trigger (slice memory.current near memory.max, or slice PSI) so AIRA proactively kills the biggest offending scope before the kernel's blind process-level OOM hits a random capped victim.
