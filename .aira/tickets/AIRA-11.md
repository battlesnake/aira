a peer session (an earlier ticket merge-gate). aira confine --delegate-ram ... -- make merge-gate: engine leg at -n16 (MemAvailable-derived) BLANKED under 3-way slice contention -> 'bringing up nodes... no tests ran in 2.02s', pytest exit=5 (0 collected). NOT OOM (no 137/cap-kill). Same --delegate-ram: non-xdist collect-only collects 16686 fine; -n8 runs the full suite clean (16663 passed). 

ROOT-CAUSE (code-read, PROVEN): the aira_xdist_governor plugin is fail-open and PER-TEST — pytest_runtest_protocol wraps _acquire_slot + _acquire_reservation in try/except->log->continue-ungoverned (both time out fail-open), pytest_configure only sets a marker, and there is NO collection hook. So the governor cannot crash a worker or cause a 0-collect; collection is untouched by it. The governor also cannot change -n (set by xdist before its per-test hooks run). 

HYPOTHESIS (unconfirmed, needs contention repro): the blank is xdist/execnet worker-BOOTSTRAP failing under confine's nice/ionice CPU-deprioritisation + 3-way contention — 16 interpreters bootstrapping under CPU starvation is likelier to strand a straggler than 8; xdist retries ('bringing up nodes') then gives up (0-collect, ~2s). Discriminating experiment: run -n16 WITHOUT --delegate-ram under the same contention; if it still blanks, the governor is exonerated.

FIX DIRECTIONS: (a) PRIMARY lever is caller-side and is NOT a new AIRA signal — heavy pytest legs should run GOVERNED (--delegate-ram) with a fixed high ceiling (-n nproc, or a bounded 8-12 to dodge the bootstrap-blank above). The xdist governor already does DYNAMIC PER-TEST scaling: each worker gates on a free CPU slot before every test, so the running-worker count self-adjusts to free machine-wide slots continuously; -n is only the CEILING the governor throttles down from (0..-n), never spawns past. The anti-pattern is a static MemAvailable-derived -n: a launch-instant dip freezes the ceiling low for the whole multi-minute run. CONFIRMED 2026-08-28: an UNGOVERNED engine leg (aira confine --memory-reserve 12G, no --delegate-ram) computed -n=min(nproc, MemAvailable/1.8)=4 from a transient ~7G MemAvailable dip and stayed pinned at 4 cores while 11/15 CPU slots + ~40G reserve headroom sat idle for minutes (/proc/meminfo is NOT cgroup-aware, so the 12G cap wasn't the cause — the static formula was). (b) NARROW nice-to-have (demoted from 'the real fix'): AIRA could expose a live free-slot count (AIRA_CPU_SLOTS_AVAILABLE) — but ONLY for callers that CANNOT ride the per-test governor (raw pytest -n with no plugin, `go test` parallelism, non-pytest parallel jobs), or to avoid over-spawning the ceiling far past nproc (idle-blocked interpreters + startup + poll + the bootstrap-blank risk). Governed suites do NOT need it — the governor scales them per-test already. (c) HONESTY GUARD (P1 if any gate swallows it): ensure exit-5/0-collect always fails the gate LOUD (pytest exit 5 is non-zero, so default make/CI fails — confirmed various' merge-gate has first-party blank-leg detection that fails LOUD). Interim workaround: XDIST_WORKERS=8 for heavy legs under contention.
