CONFIRMED, fixed by PR #15 as a DOCUMENTATION fix. Direction 1 (decouple coordinates from DelegateRAM) was rejected on evidence: (a) the authoritative spec 2026-09-01-aitest-design.md:144-149 says the aitest outer scope "launches exactly like any other job under aira confine --delegate-ram", so the code matches the spec and only the doc was wrong; (b) worker-admit fails closed unless the outer scope has a finite memory.max (admit.go:1273-1275 -> worker_admit.go:162-165 unevaluated -> supervisor.py:358-359 classifies it permanently non-retriable -> whole-run unconfined fallback), and an unpinned non-delegate launch that is not daemon-admitted is deliberately left uncapped (confine_linux.go:668-675), so wiring coordinates there would relocate the containment loss behind a path that merely looks governed. TWO CORRECTIONS to this ticket's own impact statement, both verified: the degradation is NOT silent (supervisor.py:209-216 writes one stderr warning), and the fallback is ONE worker, not min(requested, NumCPU) -- AIRA_AITEST_MAX_WORKERS_FALLBACK defaults to "1" (supervisor.py:172) and was itself stripped. TWO FURTHER DEFECTS found in the same paragraph and fixed: nothing sets PYTHONPATH so AIRA_AITEST_LIB alone does not register the plugin (a guarded conftest snippet is required, else --aitest-workers is not a valid option at all); and "admits it individually through the daemon" overstated slice accounting, since worker-admit adds no slice-ledger charge. TEST GAP CLOSED: the pre-existing TestConfineNonDelegateLaunchStripsInheritedAitestEnvironment passes RuntimeDir:"" and AppendAitestChildEnvironment early-returns on empty runtimeDir (env.go:53), so it passed identically with or without the gate; mutation-testing confirmed the new populated-RuntimeDir test fails under direction 1 while the old one still passes.
