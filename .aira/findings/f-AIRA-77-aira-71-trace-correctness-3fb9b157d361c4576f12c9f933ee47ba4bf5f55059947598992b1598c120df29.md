CONFIRMED, and there is no env off-switch. --delegate-ram unconditionally upserts AIRA_TEST_MEM_GOVERNOR=1 (env.go:153). The legacy governor gates its per-test RAM reservations on that variable ALONE (aira_xdist_governor/__init__.py:338-340), and its pytest_runtest_protocol hookwrapper (:388-389) has no xdist-worker gate, so it fires inside every aitest worker via worker.py:393. AIRA_GOVERNOR=off does NOT help: it gates only the CPU checkpoint (:164), not the RAM half. The two are exactly anti-correlated -- the only launch mode that enables aitest at all (--delegate-ram) is also the only one that arms the governor. Actions that DO work: stop registering aira_xdist_governor in conftest, or block it per invocation with -p no:aira_xdist_governor (registered by module name). Both are now documented in the generated SKILL.md by AIRA-71. IMPORTANT correction to this ticket's framing: the charges land on DIFFERENT ledgers, so it is not double-booking of one ledger. worker-admit consults no reserve ledger at all (worker_admit.go:157-288; grants held in in-process workerJobState.grants, never queue.outstanding), while the governor's confine-reserve charges the machine-wide slice ledger. Cost is redundant reservation and slice contention, not one ledger charged twice. Real resolution remains spec 2026-09-01-aitest-design.md section 3.8: delete aira_xdist_governor outright.
